# 阿里云部署说明

## 当前结论
- 当前项目可以按前端静态站上传阿里云。
- 上传内容是 `dist/` 目录里的所有文件，不是上传源码根目录。
- 如果使用阿里云 OSS 静态网站，需要同时上传 `index.html` 和 `404.html`，并把静态网站的默认首页设为 `index.html`、404 页面设为 `404.html`。
- 如果使用 ECS/Nginx，需要配置 SPA 回退，把不存在的路径都回退到 `index.html`。

## 构建命令
```bash
npm run build
```

构建成功后上传：
```text
dist/
```

不要漏掉这些关键文件：
```text
dist/index.html
dist/404.html
dist/assets/
dist/platform-tariffs.json
dist/usage-guide.html
dist/*.json
dist/ozon-wholesale-90day-pack/
dist/deli-proposal/
```

## 正式云端保存版打包
正式云端保存版必须先有 Supabase 项目，并在本地创建：

```text
.env.production
```

内容参考：
```text
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-supabase-anon-public-key
```

可以从模板复制：
```powershell
Copy-Item .env.production.example .env.production
```

填好后运行：
```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-aliyun-release.ps1
```

脚本会做三件事：
- 检查 `.env.production` 是否存在；
- 检查 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY` 是否已填写；
- 重新构建并生成正式包：
```text
release/russia-pl-calculator-aliyun-supabase.zip
```

如果没有 Supabase 环境变量，脚本会直接停止，避免误打演示包。

## 阿里云 OSS 静态网站配置
1. 打开 OSS Bucket。
2. 上传 `dist/` 目录下的所有文件和文件夹。
3. 静态网站托管：
   - 默认首页：`index.html`
   - 默认 404 页：`404.html`
4. 这样 `/p/xiongwei-chuanqi`、`/app/projects/xxx` 这类前端路由刷新时，会先进入 `404.html`，再自动跳回应用内正确路由。

## ECS / Nginx 配置
如果不是 OSS，而是 ECS 上的 Nginx，站点配置需要类似：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

这种方式比 404 跳转更直接。

## 云端保存提醒
- 当前前端已经支持 Supabase 云端项目库、公开页、发布版本和临时快照。
- 阿里云 OSS/静态网站主要负责“把网页程序打开给别人用”，它不会自动变成项目数据库。
- 用户在网页里编辑项目时，真正需要有一个后端数据库接收保存请求；当前方案里这个角色由 Supabase 负责。
- 可以理解为：阿里云 = 前台网页和访问入口，Supabase = 后台项目库、登录权限、保存记录。
- 如果只上传到阿里云但不接 Supabase，保存通常只能落在当前浏览器本机，别人换电脑或换账号就看不到你保存的新项目。
- 理论上也可以全部改成阿里云体系，例如 OSS + ECS/函数计算 + RDS/表格存储 + 登录权限接口，但这等于再开发一套后端；当前阶段用 Supabase 是为了最快实现真正多人云端保存。
- 但如果构建时没有配置：
```text
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```
线上会进入演示模式/浏览器本地模拟云端存储，别人跨设备看不到你本机保存的新项目。
- 如果要正式多人云端保存，需要先执行：
```text
supabase/migrations/20260612_online_collab_init.sql
```
然后用带 Supabase 环境变量的构建产物上传阿里云。
