# 普通商品表签收率导入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让普通商品表（CSV/TSV/非完整项目 Excel）同时导入 Ozon、WB、Yandex 三个平台的预计签收率，并在新增或更新 SKU 时保留平台设置。

**Architecture:** 保持现有 `productImport.js` 的轻量表头别名解析，不改完整项目 Excel 解析器。为三个签收率列增加独立内部字段，解析后写入 `product.platforms[platform].acceptanceRatePct`，再沿用现有 `mergeImportedProducts` 的平台级合并规则。缺失列继续使用现有平台默认值，旧表行为不变。

**Tech Stack:** 原生 ES modules、Node `node:test`、Vite/React 现有导入流程。

- [x] **Step 1: Write the failing test**

测试包含一行带中文表头的二维表，验证 `parseProductImportRows` 将三列分别写入 `platforms.ozon/wb/yandex.acceptanceRatePct`；再用同一 SKU 调用 `mergeImportedProducts`，确认只更新对应平台字段并保留已有平台设置。

```js
const rows = [
  ["SKU", "采购价 CNY", "Ozon 预计签收率 %", "WB 预计签收率 %", "Yandex 预计签收率 %"],
  ["SKU-1", 10, 83, 72, 64],
];
const parsed = parseProductImportRows(rows);
assert.deepEqual(
  parsed.products[0].platforms,
  {
    ozon: { enabled: true, salesShare: 100, model: "FBO", acceptanceRatePct: 83 },
    wb: { acceptanceRatePct: 72 },
    yandex: { acceptanceRatePct: 64 },
  },
);
```

同时覆盖 `0`、空值和超过 `100` 的输入，确保非法签收率不会悄悄进入计算层；旧表只带 SKU/采购价时仍不生成平台签收率覆盖值。

### Task 2: 实现普通商品表三平台字段映射

**Files:**
- Modify: `src/lib/productImport.js`

- [x] **Step 1: Add normalized aliases and numeric fields**

增加 `ozonAcceptanceRatePct`、`wbAcceptanceRatePct`、`yandexAcceptanceRatePct` 三个内部字段，别名覆盖中文、英文和常见 `buyout/acceptance` 写法；把字段加入 `NUMERIC_FIELDS`。

- [x] **Step 2: Parse and validate percentage values**

对三字段统一使用百分数解析：空值表示未覆盖默认值；有效范围为 `1..100`；带 `%` 的文本沿用现有 `parseNumber` 去除符号。超出范围或非数字的单元格跳过该字段，不影响同一行其他商品字段导入。

- [x] **Step 3: Write platform patches without clobbering unrelated settings**

在 `productFromRow` 中分别构造 `ozonPatch`、`wbPatch`、`yandexPatch`，只写入出现于表头且有值的签收率；Ozon 继续复用现有默认配置，WB/Yandex 只创建最小平台对象。`mergeImportedProducts` 继续按平台深合并，确保更新 SKU 时已有佣金、履约模式和类别不丢失。
